01

The problem

Every 941 names who filed it. The IRS checks that name against the first two digits of the EFIN in the manifest, not against a lookup of provider options. EFINs that start 10, 21, 32, 44, or 53 are Online Provider numbers. The return must then say OnlineFiler.

Pyramos checked Online Provider on the e-file application, so IRS issued 102192. The composer writes ReportingAgent plus PIN 17966. Those two facts cannot share a submission.

03

What the plan got wrong

Corrections

  • R0000-118-01 is real for 94x, not 1040 folklore. Same wording in Q1 v2 and v4. It inspects the manifest EFIN. Header mismatch is a separate rule, R0000-054-01.
  • Dropping Online Provider does not reissue 102192 without the 10. The digits are already baked in. IRM 3.42.10.5.2.1 generates a new EFIN while Online is temporarily Dropped, then restores Online.
  • pyramos-mef-registration.html warned that keeping OnlineFiler trips 119-01. That assumed a non-10 EFIN (OneWell 238689). With 102192, OnlineFiler satisfies 119. 118 is the RA killer.
  • Option B is not "sendable this week by flipping a constant." OneWell Scenario1.xml still has EFIN 238689, SoftwareId 12345678, PIN 1234567890, and illegal security fields. R0000-904-03 still fires after 118 is fixed unless a real Software ID has passed 94x testing.
  • Login does not send OriginatorTypeCd. Today's login probe is unaffected either way.
  • A Transmitted SOAP result is not an Accepted 941. 118 is Reject and Stop on the ACK, before F941 math.

Weakest part of this pick

IRM 3.42.10.5.2.1 is written for adding an ERO EFIN to an Online Provider application. It does not name Reporting Agent. Pub 3112 allows more than one provider option on one application and forbids a second EFIN at the same location unless IRS issues it. The six-step dance exists. Whether e-Help will run it for RA, or will require adding ERO first, only e-Help can say. Your call on whether to add ERO as a paper option to make the IRM apply literally.

How the gate worksrules · pubs · code

Key concepts. EFIN is the originator number on the return. ETIN is the transmitter number on the login. ASID is the A2A system id, here 10219201, which is 102192 plus 01. OriginatorTypeCd is ERO, OnlineFiler, ReportingAgent, FinancialAgent, or LargeTaxpayer. PIN groups are an XSD choice. You get one.

How it works. Login presents the IdenTrust cert against ASID 10219201. SendSubmissions carries a manifest EFIN and a Return header. R0000-054-01 forces those EFINs to match. R0000-118-01 then reads the first two digits of the manifest EFIN. If they are 10/21/32/44/53, the header must say OnlineFiler or the ACK is Reject and Stop. The converse is 119-01. Pub 3112 is why 102192 got that prefix. IRM 3.42.10.5.2.1 is how e-Help issues a second, non-online EFIN without permanently dropping Online Provider.

Where things live. Rule text in the extracted 941 Q1 v4 PDF. Header writer in ReportingAgentReturnXml.java. Locked type in ReportingAgentReturn.ORIGINATOR_TYPE. Tests that forbid OnlineFiler in ReportingAgentReturnTest.java. Old OneWell header in test-scenarios/941-scenario-1-orchid-q1-2026/Return941-Scenario1.xml.
