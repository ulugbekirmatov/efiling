TL;DR

Yes, you can start hitting ATS the moment the ASID shows active, and ATS is open right now, but it closes for 15 days starting September 28. Three things gate production and none of them is code: the Software Developer option and ATS pass for your own software, the Reporting Agent PIN that arrives by mail after Form 8655 and the agent's list are on file, and the one-time communications test that flips your ETIN to Production.

Save the ASID and confirm it went active

Automated Enrollment moves a new A2A Client System ID from new to active by itself once the save succeeds. There is no activate button to press and no published propagation wait. The public certificate you upload is your-issued-cert.pem (DER copy at pyramos-a2a-cert.cer). Add at least one service and at least one ETIN before Save or the form rejects. Source: Automated Enrollment External User Guide, Table 2-4 and section 4.2; Publication 4164 (Rev. 12-2025) section 4.1.6.

  1. Services to select: SendSubmissions, GetSubmissionStatus, GetNewSubmissionsStatus, GetAcks, GetNewAcks, GetAck. Login and Logout are always included.
  2. Select the ETIN whose Forms Transmission Status is Test. If the list is empty, the e-file application does not yet carry a Transmitter ETIN; stop and fix that first.
  3. Write the ASID (EFIN plus two digits) into .env as MEF_ASID together with MEF_ETIN and MEF_EFIN. Purge the OneWell values 97661, 238689, 23868900 from tests and scripts.
  4. Build the PKCS12 from private-irs.key + your-issued-cert.pem + SubCA1.txt + Root.txt. Fix the stale paths in create-pkcs12.sh before running it.

Same day

First ATS Login with the certificate

Publication 4164 says to start with Login only. Login carries the certificate signature; every later call reuses the returned SAML token. ATS host prefix is la.alt (la.alt.www4.irs.gov); production is la. The SDK's ats_endpoints.properties already points there. Run the gated login test, not mvn test, because Form941SubmissionTest is ungated and would submit. Only the network part of MefLoginIntegrationTest is behind the flag; its keystore checks always run, which is useful here.

  1. Unauthorized request fault = certificate not registered or wrong ASID. Re-check the AE screen, wait, retry, then call e-Help 866-255-0654.
  2. Authorization Failure = the service you called is not in the ASID's Selected Services.
  3. Timestamp fault = clock more than 9 minutes off MeF time. Sync NTP.
  4. Signature rejected = SHA-1. The SDK must sign SHA-256 or higher.

Before Sep 28

Get the Software Developer option and a Software ID, then pass 94x ATS

This is the step the CLAUDE.md plan does not mention. Pyramos writes its own transmission software, so it is a Software Developer under Publication 3112, and business rule R0000-904-03 in the local 2026 rule set rejects any return whose Software ID has not passed testing for the form family and tax year. A Reporting Agent using third-party software skips this; Pyramos cannot. The Software ID is issued when you save the software-package questionnaire in e-Services (quarterly format like 2699NNNN). Tell e-Help you are ready to test; there is no self-service scheduler. Publication 5078 section 3.5.1 sets the floor at one accepted Form 941 scenario; the TY2026 94x ATS page lists three Form 941 scenarios plus one 941-X.

  1. Open the e-file application and add Software Developer if absent. Publication 3112 says Software Developer-only firms skip suitability, so this should not restart the 45-day clock, but the IRM says adding an option puts the application in Resubmission Required. Confirm with e-Help.
  2. Complete the software package questionnaire for 94x quarterly, tax year 2026. Note the Software ID; it goes in the return header SoftwareId.
  3. Submit ATS scenario 1 (Orchid Incorporated, EIN 00-3000004) signed the Reporting Agent way. The TY2026 scenario sheet says to use whichever signature option applies to you. ATS EINs start with 00 (rule R0000-148).
  4. Ask e-Help which Receipt IDs they will score for Pass. Publication 5078 and the live scenario page disagree on whether scenario 4 is 941-X or the Online PIN scenario.

Before Sep 28

One-time A2A communications test, then ETIN to Production

Transmitters do one error-free communications test on the method they will use in production (A2A). After it, IRS moves the ETIN's Forms Transmission Status from Test to Production. Publication 5078 sections 2.1.3 and 2.6. No published turnaround for the flip. Publication 3112 names Reporting Agents as well as Transmitters for this test. Plan on two ETINs: the Software Developer ETIN stays in Test year-round (Publication 5078 section 2.1.2), and the Transmitter ETIN is the one that flips to Production. Once flipped, that ETIN can no longer send to ATS, so keep the Test ETIN for the R10.A cutover below. Sundays 12:00 to 9:00 a.m. ET MeF accepts submissions but issues no acknowledgements.

Parallel, start today

Form 8655 per client, the Reporting Agent's List, and the RA PIN

Publication 1474 (Rev. 4-2026) section 01.02 requires the initial Form 8655s and the Reporting Agent's List before or with the e-file application change that adds Reporting Agent. Publication 3112 says adding the Reporting Agent option validates that the application EIN has a Form 8655 on file. The PIN is 5 digits, system-generated, not self-selected, and mailed USPS to the firm address (Publication 4163 section 3.6.4); you can also request it from e-Help. Business rules R0000-187 and R0000-188 reject a PIN that is all zeros or that does not match the e-file database.

  1. Collect a signed Form 8655 (Rev. January 2024) from each client. Signer must be able to bind the entity.
  2. Send the initial list plus 8655s. Paper or fax to Ogden RAF Team, fax 855-214-7523, max 25 forms per fax. IRS returns a validated list within about 30 days (IRM 21.3.9.3.6). Above 100 clients per week the only electronic route is SLFT B2B.
  3. Add the Reporting Agent provider option to the e-file application after the 8655 is on file. Plan up to 45 days for approval.
  4. Keep every original 8655 at the principal place of business until the assessment period for the last return filed under it expires.

Code: Reporting Agent return header and multi-tenant filer

Verified against ReturnHeader94x.xsd 2026Q1 and the 941 business rules PDF in this repo. OriginatorTypeCd takes ReportingAgent. The signature choice becomes ReportingAgentPINGrp with three required children. ReportingAgent94XFilerGrp is optional in the XSD but rule EMPL-003 rejects a ReportingAgent return without it, so treat it as required. The filer block stays the client's EIN, name, and address; rule R0000-901-01 checks EIN and name control against the IRS database.

  1. test-scenarios/941-scenario-1-orchid-q1-2026/Return941-Scenario1.xml:47-60 still carries EFIN 238689, OnlineFiler, and OnlineFilerPINGrp. Rewrite it as the ATS payload.
  2. ReturnXmlGenerator.java does not write the originator or PIN groups at all; the newsend path takes caller-supplied XML and never checks it says ReportingAgent or that its EIN matches clientEin. Add both checks at the boundary.
  3. SubmissionController.java:239 hardcodes TIN 003000004 and :225 a nonexistent OneWell path. SubmissionService.java:288 hardcodes 941.
  4. Rule R0000-118-01 forces OriginatorTypeCd to OnlineFiler when the manifest EFIN starts with 10, 21, 32, 44, or 53. Pyramos's EFIN must not start with those or every ReportingAgent return rejects and stops.
  5. Purge OneWell values from MefLoginIntegrationTest.java:37, Form941SubmissionTest.java:65,159, test-mef-login.sh:69,74, and NewSendManifestXmlTest.java:23,48.
  6. Real logout via LogoutClient and session expiry are still stubs (MefClientService.java:210-245). At ATS volume this matters less; fix before production.

Oct 13, 2026

ATS reopens on WSDL R10.A for filing season 2027

When ATS returns on October 13 it runs the tax year 2026 / processing year 2027 WSDLs (R10.A), and production requires them for processing year 2027. Any testing you do after October 13 is against that release. The A2A Toolkit v16 in this repo was generated from WSDL 10.9 (its release notes say so), which is what ATS runs today. The WSDLs in sdk-reference/extracted are older still (R10.3 markers). Download the R10.A WSDLs and the matching toolkit from the e-Services Secure Object Repository before October 13 and rebuild the SDK reference. SOR delivers them only to applications that carry the Software Developer option with a 94x tax type, and SOR messages purge after 60 days, which is one more reason to add that option this week. The 94x quarterly 2027 schemas start ATS on November 1, 2026.
