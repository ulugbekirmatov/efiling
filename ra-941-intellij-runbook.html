Run ReportingAgentReturnTest from the gutter

mef-spring-boot-integration/.env  (gitignored)

Create the .env file in the module directory

The Spring test boots the full application context. On boot, DotenvEnvironmentPostProcessor reads .env from user.dir, which for an IntelliJ JUnit run is the working directory of the run configuration. Since that defaults to the module directory, the file must live at mef-spring-boot-integration/.env, not at the repo root. Real environment variables still win over the file.

# --- A2A session (MefSdkConfig) ---
MEF_ETIN=<Pyramos ETIN>
MEF_EFIN=<Pyramos EFIN>              # 6 digits; 238689 (OneWell) and 000000 are refused
MEF_ASID=10219201                    # the gate hardcodes this exact AppSysID
MEF_KEYSTORE_PATH=/absolute/path/to/pyramos.p12
MEF_KEYSTORE_PASSWORD=<keystore password>
MEF_KEYSTORE_TYPE=PKCS12
MEF_KEY_ALIAS=<alias inside the p12>
MEF_KEY_PASSWORD=<key password>

# --- Reporting Agent originator (ReportingAgentProperties, mef.reporting-agent.*) ---
MEF_RA_PIN=<5-digit Reporting Agent PIN>
MEF_SOFTWARE_ID=<8-char Software ID>
MEF_RA_EIN=<Pyramos EIN>                # 003000004 (Orchid, the client) is refused
MEF_RA_NAME=PYRAMOS SOFTWARE LLC
MEF_RA_NAME_CONTROL=PYRA
MEF_RA_ADDRESS_LINE1=<street>
MEF_RA_CITY=<city>
MEF_RA_STATE=<2-letter state>
MEF_RA_ZIP=<zip>

Not needed: MEF_USERNAME/MEF_PASSWORD (login is certificate-only), A2A_TOOLKIT_HOME (defaults to classpath:mef_config), and the environment switch (application.yml already sets mef.sdk.environment: ATS).

Checkpointgit status does not list .env. The keystore path points at the Pyramos PKCS12 (subject O=Pyramos Software LLC), not the old OneWell one. Both share CN=c2s.pahealthmanagement.org, so check the O=.

Run → Edit Configurations…

Create the JUnit run configuration with the gate property in VM options

The test class carries @EnabledIfSystemProperty(named = "mef.integration.test.enabled", matches = "true"). JUnit reads a JVM system property, so the switch goes in the VM options field. Putting it in the Environment variables field does nothing and the test reports as skipped.

  1. Run→Edit Configurations…→+→JUnit. Name it RA 941 ATS (LIVE) so the name warns you.
  2. Test kind: Class. Class: com.irs.mef.reportingagent.ReportingAgentForm941AtsTest.
  3. Use classpath of module: mef-spring-boot-integration. JRE: 17.
  4. Click Modify options→Add VM options and paste:
-Dmef.integration.test.enabled=true
--add-opens java.base/java.lang=ALL-UNNAMED
--add-exports java.xml/com.sun.org.apache.xerces.internal.dom=ALL-UNNAMED
--add-exports java.xml.crypto/com.sun.org.apache.xml.internal.security=ALL-UNNAMED
--add-exports java.xml.crypto/org.jcp.xml.dsig.internal.dom=ALL-UNNAMED
  1. Working directory: $MODULE_WORKING_DIR$ (the default). This is what makes .env, the fixture paths, a2a_sdk.log.*, logs/ and the NewSend journal data/newsend-journal.jsonl all resolve relative to mef-spring-boot-integration/.
  2. Apply. Do not add Form941SubmissionTest or MefLoginIntegrationTest to this configuration; they share the same gate and would also go live.
↳

The four --add-opens/--add-exports lines are copied from the pom's spring-boot-maven-plugin block. The pom passes them to spring-boot:run but not to Surefire, and the existing login test has run under Maven without them. They are harmless here and remove InaccessibleObjectException as a variable.

CheckpointRunning the configuration with an empty .env fails immediately with ReportingAgentValidationException: MEF_EFIN is required. That proves the gate is armed and the property reached JUnit. A grey "ignored" result means the property did not.

Gotchas that cost time

  • VM options, not environment variables. @EnabledIfSystemProperty reads System.getProperty. An env var named mef.integration.test.enabled is ignored and the test shows as skipped.
  • Never run the test folder or a bare mvn test with the gate property set. Form941SubmissionTest (OnlineFiler, OneWell values) and MefLoginIntegrationTest use the same property and would also hit ATS.
  • .env location is the working directory. If you change the run configuration's working directory to the repo root, move the file too. The fixture helper tolerates either directory; the dotenv loader does not.
  • ASID is fixed at 10219201. The gate throws on anything else. It is compared against the session config only and must never appear in the Return XML; the offline test asserts that.
  • EFIN must match in two places. The originator EFIN comes from MEF_EFIN and the gate re-checks it against the same value, because the submission id prefix, OriginatorGrp, and the manifest all share it. ETIN is a different number and only authenticates the session.
  • Java 17 only. Java 8 is too old for Spring Boot 3; 21 and 25 break the Metro stack the SDK uses.
  • Concurrent session errors after a failed run. Logout is local-only and never calls LogoutClient, so a killed run leaves an IRS session open. Wait a few minutes before retrying.

Troubleshooting by error text

Match the first line of the failure, not the stack trace

Cannot resolve symbol / red gov.irs.mef importsIDE, before running

The SDK jar is not in ~/.m2 (step 2) or Maven has not re-imported. Run the install:install-file command, then Reload All Maven Projects. If @Data getters are red, enable annotation processing (step 4).

Tests ignored / class shows grey with no assertionsJUnit

The gate property is missing. Open the run configuration, click Modify options→Add VM options, and confirm -Dmef.integration.test.enabled=true is in that field.

ReportingAgentValidationException: MEF_RA_PIN is required (or any MEF_*)step 1 of the flow

Either the variable is missing from .env or the file is not in the working directory. Confirm the run configuration's working directory is $MODULE_WORKING_DIR$ and the file sits at mef-spring-boot-integration/.env. The factory reads Reporting Agent fields through mef.reporting-agent.* in application.yml, which map one-to-one to the MEF_RA_* names in step 6.

MEF_EFIN 238689 is the OneWell originator; refusestep 1 of the flow

You reused OneWell-era values. The PR deliberately blocks EFIN 238689, stand-in EFIN 000000, and Orchid EIN 003000004 as the agent EIN. Replace with Pyramos values from the e-file application.

MEF_ASID must be 10219201 (A2A AppSysID). Refusing to file under '…'step 2 of the flow

Set MEF_ASID=10219201. The old OneWell ASID 23868900 is the usual culprit.

MEF_KEYSTORE_* must be set or login fails with a certificate errorsteps 2 and 4 of the flow

Both MEF_KEYSTORE_PATH and MEF_KEYSTORE_PASSWORD must be non-empty; the path must be absolute. If login still fails, the certificate may not be registered against ASID 10219201 in Automated Enrollment yet. The raw IRS fault is in a2a_sdk.log.*, not in the JUnit output.

IllegalStateException: Fixture not found: test-scenarios/941-reporting-agent-orchid-q1-2026/…offline or live

The working directory is neither the module nor the repo root. Reset it to $MODULE_WORKING_DIR$.

InaccessibleObjectException / module java.xml does not export …live test, during login

The --add-opens/--add-exports lines from step 7 are missing from VM options, or the run is on a JDK newer than 17.
