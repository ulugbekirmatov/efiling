Make the MeF repo agent-friendly

What the transcripts say about how you steer agents, which mistakes the commit history proves they repeat, three prototypes that settle the open design questions, and an eight-unit plan to the shape where a change that looks right from one file is right for the whole repo. Nothing landed on main; every prototype lives on spike/agent-friendly.

TL;DR

Two earlier guardrail passes fixed the mistakes that fit in a test. What is left is structural: a dead legacy send path the docs still call "working", a Reporting Agent composer that only a test can reach, one unlocked IRS session shared by two paths, and facts kept in three to six places. The plan collapses sending to one package with one public door, makes the scenario directories the only list, and generates every doc figure. Three spikes already prove the riskiest claims: the legacy path deletes cleanly (−2,068 lines, 6 of 10 open traps gone), a doc-reference guard goes red on real stale lines and caught the next one live, and the three scenario lists collapse to one in 73 lines.

How you steer agents (recall)

Every prior transcript under the MeF project was mined: 39 chats from 2026-09-30 to 2026-10-27 (this session excluded). Of 323 user-slot turns, 130 are yours; the rest are harness notifications landing in user slots. The miners found 17 corrections across 11 chats. An adversarial refuter then re-read each one in the raw transcript and kept the classes with two or more sessions.

The pattern

  • Open with a slash command, a one-paragraph goal, and a seat budget, then step away. Nine chats start with /poteto-mode; seven name a per-model budget ("5 opus 5.5 and 10 grok 4.7 and 5 sonnet 5.5"). You act at gates: launch, merge, push.
  • Terse lowercase imperatives, one-word approvals. "checkot main and pull", "swithc to main", "contine"; "yes", "yep", "go ahead start implementing.", "merge all the PRs".
  • Redirect with a new fact, not a critique. "btw i have the latest toolkit A2A_Toolkit_Version17.0.zip in downloads folder"; "btw it must be C2S page". Gaps arrive as short questions: "what about 940?".
  • Verify by looking. Screenshots as input ("[Image #7] now fixed?"), "open it in browser", "do all the numbers in the screenshot add up correctly?", re-run on the real file.
  • Rules go into files, and when prose is not enough, into structure. "write it in claude md or any other related place"; a pasted "## Environment & Artifacts" block; two /pstack:correct passes (PR #10, PR #15); the TaxBandits ban became a PreToolUse hook after the written rule failed.
  • When the agent balks, you run the command yourself. ! git push after a permission denial; gh pr merge --match-head-commit after the bare command failed.

The code today (architect, grounding)

Three Sonnet explorers traced the current send path, the legacy generation and the c2s-web UI; an Opus explainer reconciled them and spot-checked the code. Thirty-two facts came out; these are the ones the plan acts on.

  • Composer and gate are test-only. ReportingAgentReturn.compose, ReportingAgentAtsGate.open, ClientReturnBody.load and fromEnvironment have no caller in src/main outside their package. The HTTP path takes raw returnXml and never reads OriginatorGrp, so the R0000-054-01 three-way EFIN rule is held by one test and a gate that compares MEF_EFIN with itself.
  • One unlocked session. MefClientService.java:34-37 holds the ServiceContext in non-volatile fields; only newsend takes a lock (NewSendSubmissionService.java:67); ack, status and login touch it unlocked.
  • Hand-synced lists. Scenario ids in four places (enum, shell case, two JSON files; the UI reads one, so the 940 scenarios never appear). Six state-to-tone maps in c2s-web. The efile namespace three times. The processing zone three times. ATS literals three times.
  • Two ways to do one task. Two send implementations, two submission-ID generators, three manifest renderers, two exception hierarchies, two masking policies.
  • Prose holds the invariants. “No retry on SendSubmissions”, the session-lock gap, the F940 placeholder, “reuse getCurrentServiceContext()”: all comments. CLAUDE.md runs 2,546 words with 14 prose rules; 3 rule-table rows are docs-only.

A. Can a test catch stale docs? yes

DocReferenceGuardTest scans tracked markdown for backticked symbols and paths that no longer exist, exempting lines marked deleted or retired. On main it fails with 10 hits on 9 lines, among them CLAUDE.md:116 SchemaPreflight and the Form941XmlGenerationTest references. After six doc fixes the full suite is green. Commits 6619aa0, d0f2be4. One rule was loosened while building it: a bare file name with no slash counts as existing when any tracked file has that name, because the literal rule gave about 25 false hits on references like MefClientService.java:69-203. Paths with a slash must still exist.

Caught live

When spike B's deletion was merged on top, the guard went red again with 13 hits on 11 more lines in CLAUDE.md and CODE_MAP.md that still pointed at the deleted classes. That is class 1 happening in real time, on the very change that deleted the code, and the guard stopped it. Docs repaired in 600b455.

B. Can the legacy generation be deleted? yes, in one commit

Deleting SubmissionController, AcknowledgementController, SubmissionService, StatusService, four DTOs, the GetNewAcks methods and three dead helpers removes 8 routes and 2,068 lines. Nothing in the current path needed a deleted symbol; the only test casualties were the live-only Form941SubmissionTest and two GetNewAcks cases. Gone with it: the stubbed status route, the fabricated archive path, the ack-queue drain, the inline submission ID, the hardcoded 941 type code, the ungated live endpoint. Still there: retry-everything, every MefException to 500, the unlocked session, dead config trees. Commit 6e0bb7e.

C. Can the three scenario lists collapse to one? yes, cheaply

A test first proved the three lists agree today (7 ids) and that it reports a divergence. Then AtsScenario became a record read from both scenarios.json files and run-ra-ats-test.sh resolves ids with jq instead of a hard-coded case. 73 insertions, 100 deletions, suite green. Commits 498e145, cd516ea. The target shape goes one step further and makes the scenario directories themselves the list.

  • Does c2s-web use the server-rendered /api/inspector page? No reference under app/ or its README.

Target shape (architect, synthesis)

What is demonstrated and what is designed

Only two mechanisms below have run: the symbol-and-path doc guard (spike A) and the deletion of the legacy generation (spike B), plus the one-list collapse (spike C). DocCommandGuardTest, RejectLedger, the LocalRule corpus, FormSpec with a sealed binding and the ./mef script are design, not yet code. Where a table says “would have caught”, read it as the designed check’s claim unless the row names a spike.

Four design candidates ran in parallel (two Opus, two Sonnet) against the same grounding and rubric; a cross-judge scored them. All four converged: delete the legacy generation, one typed entry point with the composer on the production path, one session owner with one lock, EFIN derived from one object, a sealed form readiness for 940, one scenario list, a ./mef script whose exit code comes from a sealed verdict. The judge and I split the tie between the two Opus designs on different grounds, so the base is candidate 1 (smallest API, least machinery) with candidate 2's boundary grafted: everything that can reach the IRS lives in one package, so javac refuses an import from outside.
