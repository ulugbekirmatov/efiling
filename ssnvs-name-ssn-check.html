Check W-2 names and SSNs with SSA before the wage file goes in

A W-2 whose name and SSN don't match SSA's records goes into SSA's suspense file. The employee's earnings don't post to their record, and the employer gets mismatch notices months later. SSA's SSNVS lets a filer check every name and SSN pair first, in bulk, through Business Services Online. This branch builds the upload file from C2S data and turns SSA's answer into a fix list.

The two-sentence version

Export the employer's W-2 people from C2S, then ./ssnvs.sh build writes a BSO-ready SSNVS file and lists anyone who can't be sent.

Next day, ./ssnvs.sh results maps SSA's answer back to employee ids and writes fixes.csv. Fix those W-2s before you build the EFW2 file.

SSNVS is SSA's check, not IRS TIN Matching

The two services get mixed up because both "match a TIN". They serve different filings.

ServiceWho runs itForBulk limit
SSNVSSSA, in Business Services OnlineW-2 employees, current or former, for wage reporting only250,000 per file, results usually next business day
TIN MatchingIRS e-Services1099 payees, for payers in the IRS Payer Account File100,000 per file
SSA forbids SSNVS for potential hires, contractors, or identity checks. A mismatch alone is not grounds for action against an employee. The runbook and fixes.csv actions say so.

Pyramos registers in BSO once, under its own firm, and requests SSNVS access. SSA then mails an activation code to the firm's IRS address of record. Allow about two weeks; the code expires after 60 days. Sign-in is Login.gov or ID.me. Each upload carries the client's EIN, typed on the BSO page. The record itself has no EIN field, so one file covers one employer.

The operator flow

  1. In DBeaver, run sql/ssnvs_w2_people.sql for one legal company and tax year. Use the sed copy from the runbook, because PostgreSQL rejects the empty C2S editor markers. Export the result as CSV.
  2. ./ssnvs.sh build --csv export.csv --out out writes out/<ein>/ssnvs.txt (plus a zip over 500 records), holdbacks.csv, notes.csv, and manifest.json.
  3. python3 ssnvs_check.py request out/<ein>/ssnvs.txt is a second opinion. The checker was written from the SSA handbook alone and shares no code with the builder.
  4. Upload in BSO with the client EIN. Keep the confirmation number.
  5. Next business day: ./ssnvs.sh results --dir out/<ein> --results ssa.txt writes fixes.csv by employee id.
  6. Fix box e or the SSN in C2S and regenerate the W-2s. Then re-verify and build the EFW2 file.

The full how-to is mef-spring-boot-integration/SSNVS.md.

The record, from the handbook

Both researchers read SSA's SSNVS Handbook (updated January 2025), pages 18 to 21, one on opus and one on grok. They agree on every position. I re-read the extracted PDF text myself.

pos 16-28   last name (13)          29-38  first (10)   39-45  middle (7, optional)
pos 46-53   birth date MMDDYYYY or blanks              54-89  blanks

Names must be letters only: no hyphens, apostrophes, spaces, periods, suffixes, or titles. So O'BRIEN-SMITH JR is sent as OBRIENSMITH, and MARY ANN as MARYANN.

What the builder decides for you

The name SSA checks is the W-2 box e name

The C2S W-2 stores first and middle as one string (box_e_first_middle). HR and ADP only decide where to cut it. The cut is recorded per person as name_source: HR_FULL HR_INITIAL ADP_FULL SINGLE_TOKEN HR_FIRST_PREFIX GUESSED. A guessed cut is still sent with a note. On a code 5, fixes.csv says to confirm the cut first.

Held back versus flagged

Held, not sentSent with a note
NO_SSN, SSN_NOT_9_DIGITS, SSN_SHAPE_NEVER_ISSUED, W2_FIELDS_BLANK_OR_DISAGREE, W2_EIN_DIFFERS, W2_EIN_BLANK, LAST_NAME_BLANK, FIRST_NAME_BLANK, NAME_INVALID_CHARACTER, DUPLICATE_SSN (every holder), DUPLICATE_EMPLOYEE_ROW SSN_DIFFERS_FROM_HR (the W-2 SSN is sent, because that is what gets filed), FIRST_MIDDLE_SPLIT_GUESSED, SUFFIX_OR_PREFIX_DROPPED, NAME_TRUNCATED, DUPLICATE_FIRST_LAST, two birth-date-omitted notes, SEVERAL_W2S

PII stays where SSA needs it

Only ssnvs.txt holds SSNs, names, and birth dates, because SSA requires them. The manifest, holdbacks, notes, fix list, stdout, exception messages, and every toString carry employee ids and codes only. SsnvsPiiGuardTest enforces that, last four digits included. ssnvs-out/ is gitignored.

An uploaded file is never overwritten by accident

Results need the exact file that was uploaded. build refuses to replace a directory that has a manifest and no fixes.csv unless you pass --replace.

How the shape was chosen

Three runners each designed a whole shape: Java in the Spring app (opus), a Python CLI (grok), and a C2S page (grok). A Fable judge scored them against a six-point rubric.

ShapeScoreWon onLost on
A. Java domain core25Value types that refuse illegal names; tests run in CI (mvn test is the only CI gate)REST server, run store, and file splitting were more than the job needed
B. Python CLI25Smallest surface: two commands, one manifestIts tests would not run in CI
C. C2S page21No PII export on a laptopNo zip, browser-side SSNs, bare query params

Shipped: A's Java core with B's two-command CLI in place of the REST server, plus C's file gates. It runs as SsnvsCli with no Spring context, so GlobalExceptionHandler never sees a message.

Adversarial review

Fable, opus, and two grok reviewers read every file and probed the code with synthetic inputs. Everything below was fixed, each fix with a test that fails without it.

Consensus findings (raised by 3 or 4 of the 4 reviewers)
  • The query silently dropped W-2s whose company code maps to no legal company. It now also selects W-2s whose box b EIN equals the FEIN, and the notes add a check query for W-2s with a NULL tax year.
  • A suffix in box e first/middle was sent as the middle name: JOHN A JR went out as middle AJR. One tokenizer now serves both the split and the name rules.
  • The checker's pair mode did not compare SSNs. It now compares positions 6 to 9 for every code, and all nine digits for codes 1 and 5.
  • Unicode dashes, typographic apostrophes, and no-break spaces held people for nothing. The suffix list was too short (V, ESQ, 3RD).
  • A rebuild between upload and results destroyed the uploaded file, and a failed results run left a stale fixes.csv.
Single-reviewer findings acted on
  • critical The documented DBeaver run could not parse (both groks). I confirmed it with PostgreSQL's own parser (pglast): a syntax error at GROUP. The sed copy parses.
  • A CSV with more than one EIN is now an input error (opus). Box e name agreement in SQL is case-insensitive (groks). The samples moved to target/ (Fable). The fake SSA results use literal handbook positions (opus). The checker now runs inside mvn test (opus).
  • Mine, found while reviewing the fix: the middle-name suffix set swallowed a real middle initial V. Fixed, with test middleInitialV.
Kept as designed
  • Duplicate first and last name stays a note, not a hold. SSA's sentence about it is in the online section and says "may not". Holding would stall two real employees named John Smith.
  • ß becomes SS, which can push a 13-letter name past the field. This is rare and sends the usual transliteration.

Open decisions

  1. Push and open the PR. The six commits are local on feature/ssnvs-bulk-file, rebased onto origin/main. They don't depend on your unpushed feature/w2-accuwage-files.
  2. Ask BSO support (1-888-772-2970) about line endings and case. The handbook doesn't say whether files use CRLF or LF, or uppercase letters. The tool writes uppercase ASCII with CRLF, the same as Excel .prn and EFW2.
  3. Box e versus HR legal name. The tool verifies the name printed on the W-2, which is the right check before filing. Say so if you wanted the HR legal name instead.
  4. Register the query in C2S? It isn't needed for the DBeaver flow. The QID stays 0 until a C2S page needs it.
  5. Docs drift found along the way. MeF/c2s/queries.md:101-115 teaches bare numeric params, while claude-projects enforces quoted-then-cast. The W-2 dashboard's CLAUDE.md says marker SQL runs in DBeaver after you replace the placeholders, and PostgreSQL rejects it.
  6. BSO access for Pyramos. Request SSNVS access now. The mailed activation code takes about two weeks.
