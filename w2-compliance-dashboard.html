W-2 compliance dashboard

Before anyone uploads W-2s to SSA, a payroll operator can now open one C2S page and see, per legal company, whether the raw paychecks, the stored W-2s, the W-3, the four 941s and the 940 agree to the cent. Every disagreement is named, with the IRS rule it breaks.

In two sentences

Eight read-only queries pull the year's paychecks, W-2s, W-3s, 941s, 940s and tax parameters per legal company. A rule table of 85 checks in the page compares them and shows errors, warnings and info notes, all of it testable offline in Node.

What the operator sees

Company rail

Every legal company (FEIN) for the year, with a red, amber or green status and error counts. Sibling hr_company codes under one FEIN roll up together, like the 941 and 940 do. A banner above the rail shows problems that apply to every company, such as a wrong FUTA wage base in onepay_tax_parameter.

Findings tab

One card per finding: severity, check id, the expected and found amounts, the rule in plain words and a link to the IRS source. A filter limits it to errors, warnings or info. Employee findings link to that employee's paychecks.

Employees tab

Boxes 1 to 6 as computed from raw paychecks next to the stored W-2. A cell that differs is highlighted with the diff. The SSN shows only its last 4 digits.

Totals tab

Each measure side by side: raw paychecks, W-2 sum, W-3, 941 Q1 to Q4, 941 year and 940. Each quarter gets a card of 941 lines (form vs raw), and a 940 card compares lines 3 to 17 against raw FUTA data.

Paycheck drill-down

Click an employee to load their final and pending paychecks. The drill-down proves that the paychecks add up to the yearly totals the checks used.

Safety rails

While a query has no QID it shows "queries not registered" and calls nothing. It refuses to judge partial data when the platform returns fewer rows than total_count. A form that isn't due yet appears as info, not an error.

The IRS matching program

SSA and IRS compare four W-2 totals with the four 941s each year: federal income tax, SS wages, SS tips and Medicare wages. Those four comparisons are errors. Box 1 vs 941 line 2 and Additional Medicare wages are warnings, because legitimate differences exist.

How to put it live

  1. Paste each sql/w2c_*.sql file into the C2S query editor. The platform assigns the QID. Each file header lists its parameters and output columns.
  2. Put the eight QIDs into the eight var W2C_..._QID = 0; lines of w2_compliance_dashboard.js, and record them in the folder's CLAUDE.md QID table. Never guess a QID.
  3. Paste w2_compliance_dashboard.js as a C2S page.
  4. Optional audit path: every query runs in DBeaver once you replace ${req.xtax_year}, ${req.xlegal_company_id} (0 = all) and ${req.xmin_payroll_status} (4).

How it was checked

Tests that can fail

Every check has a test with literal cents. The test writer worked from the spec without reading the implementation. Mutating the SS wage base, the FUTA base, the FUTA rate or EIN normalization fails 2 to 5 tests each. Running the new tests against the code from before the last round fails 6 of them.

Four review rounds

Opus, Sonnet and Grok reviewed tax rules, SQL semantics and edge cases on separate briefs. That surfaced 31 fixes in round 1 and 6 more in round 2. Defects found by two models independently were fixed first.

Real browser

The page ran in headless Chrome with stubbed platform globals and fixture data. All tabs, the drill-down, year switching, the truncation guard and the not-registered panel were exercised. No console errors appeared. This used a harness, not the live C2S platform.

Repo rules

The page is ES5 only. The validators for transaction SQL, immutable IDs and SQL conventions are clean. There is no public. prefix, and no SSN-shaped value appears in code or fixtures. All QIDs are 0 with a TODO.

Not verified: the queries have never run against the real database, because live DB access is off for Claude sessions. Running them once in DBeaver for one company is the first real test.

Open decisions

These need you. Each is also listed in the folder's CLAUDE.md.

1. Which payroll status counts as final?

Today it is status 4 (Sent). Paychecks below that are counted and reported as info, never dropped. Should status 3 (Approved) count too, and what status do ADP-imported history rows carry?

2. Which 941 column holds line 5b SS tips?

onepay_941_form has both line5a_tips and line5b_tips, and no 5b tax column. The checks read line5b_tips.

3. Closed or seasonal businesses

After the first 941 of the year, IRS expects one every quarter. The 941 table has no final-return flag, so a business that closed in Q3 shows a Q4 q941-missing error. Is there a flag elsewhere?

4. SSN source and enrollment plans

The HR match uses hr_employee.government_no. Is that what the W-2 generator uses? Do employee-paid enrollment payments only ever hold section 125 plans? If a 403(b) or 457 deferral sits there, 940 line 4 is overstated.

5. Comment cleanup in test files

The comment pass removed 63 comments from the page. Its edits to the test files were blocked by the permission classifier because the folder is untracked, and one stale comment ("stop before section 3") remains in the page. I did not apply those by hand. Approve them, or leave them.
