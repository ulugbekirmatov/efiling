How W-2 e-filing fits this repo

In two sentences

A W-2 cannot ride the MeF send. FormType rejects it, and the IRS manifest list has no W-2 code.

Build a separate Social Security Administration wage file, keep the exact bytes, and have a person upload it. The 941 path stays where it is.

A W-2 posted as a return never leaves the app

Posting form type W2 dies at the door

Pyramos already files Form 941 for a client. The live send is POST /api/mef/newsend/submissions. The body field formType is parsed by a closed list of employment-tax returns. W2 is not on that list, so the request becomes HTTP 400 before any IRS call.

The IRS schema in this repo would refuse the same code. efileAttachments.xsd for 2026Q1v4.0 enumerates returns such as 940, 941, 943, 944, 945, 1040, and 1120. It has no W-2 value. Copy A of Form W-2 goes to the Social Security Administration as a fixed-width file, not as a MeF return.

Orchid shows which dollars have to match

The accepted 941 is 1000. The corrected quarter is 2500.

ATS scenario 1 is Orchid, EIN 003000004, first quarter 2026. That 941 was accepted. It reports wages of 1000.00, federal income tax withheld of 100.00, Social Security wages of 1000.00, and Medicare wages of 1000.00. Scenario 4 is a 941-X for the same employer and quarter. Column 1 replaces those four amounts with 2500.00, 250.00, 2500.00, and 2500.00.

Column 4 of the 941-X reuses wage element names for tax. The Social Security figure there is 186.00, which is 1500 times 0.124. A wage file that copies every element named like wages will file the tax as if it were wages.

Form 941 itself has no W-2 element. The only certification is on Form 941-X. FiledW2W2cCorrWageTaxCertInd is required, and the only legal value is X. Checking that box does not file a W-2.

The NewSend journal cannot supply these amounts. It stores a SHA-256 of the return XML and omits the XML. A pre-generation check has to read the payroll ledger, or a copy of the return that was actually kept.

What to build

The wage file is its own document. It is not a new value on FormType. Adding W2 to that enum would only move the rejection from our 400 to an IRS reject, because the manifest schema still has no such code.

  1. Read one calendar year of employee totals from the payroll database. That database is not in this repo. The sibling DDL names onepay_employee_tax_payment with tax_amount and taxable_wages, keyed by tax_type_id. The lookup table onepay_tax_type has no seed rows in the DDL, so the codes for federal income tax, Social Security, and Medicare live in the database.
  2. Write one fixed-width file for the year. Publication 42-007, tax year 2026, says each record is 512 bytes. One submitter record, then each client, then a final record. A person runs AccuWage and uploads the file in Business Services Online. There is no test flag and no MeF session in this step.
  3. Keep the exact bytes and their hash. A person pastes the Wage File Identifier from the upload receipt. The app stores that identifier next to the bytes.
  4. If SSA returns the file, resubmit those same bytes. Publication 42-007 puts the resubmit flag in RA position 29 and the prior identifier in positions 30-35.
  5. If SSA has already completed the file and the data is wrong, write a different file. Publication 42-014 uses 1,024-byte records. That writer does not share a boolean with the original.
The 941 stack cannot sign this file. Login uses the IdenTrust certificate, the ETIN, and the ASID. The return jurat is a 5-digit Reporting Agent PIN. The wage file is signed by an 8-character BSO User ID in RA positions 12-19, belonging to a person. Form 8655, as described in the existing research page, authorizes 94x returns and does not authorize W-2 filing. That 8655 reading is not encoded in Java.

The two files

Both layouts were read from SSA text extracts of the tax year 2026 publications. The PDFs are not in the repo. Field positions below are the ones checked in those extracts.

Payroll rows this repo does not contain claude-projects DDL

c2s/ documents a separate platform. Earnings sit on onepay_employee_earning. Taxes sit on onepay_employee_tax_payment. hr_employee stores social_security_last_five_number and an address. The only full government-identifier column in that DDL is adp_employee.government_no. Nothing in the DDL names it as the SSN. No function in this repo rolls a calendar year into W-2 boxes.

State copies are a later file, not this one w2-efile-research.html

The research page lists eleven jurisdictions. Ten want an annual wage file. New York wants quarterly NYS-45 wage detail, not a W-2. Pennsylvania, Maryland, Ohio, and New Jersey are not an unmodified copy of the SSA file. Georgia's state-record spec was not read. Ten of the eleven due dates on that page are derived. No Java in this repo builds any of those files. Ship the federal file first.

Gotchas

Easy to get wrong

  • The legacy manifest hardcodes 941. Sending a wage file through that endpoint would label it as a 941.
  • Electronic Wage Reporting Web Service is closed to new consolidators. The research page quotes SSA as not accepting new users. Upload stays in the browser.
  • There is no test environment. Every upload is a live filing. AccuWage does not check names against SSNs.
  • A returned file is resubmitted whole, as EFW2, within 45 days. A completed file with bad data is EFW2C, or W-2c Online. Those are different artifacts.
  • Whose EIN goes on the employer record for a Reporting Agent is still an inference. Publication 42-007 was not found to use the words "reporting agent." Confirm the client EIN placement with SSA before a live file.
  • w2-efile-research.html still says the MeF side has no persistence and that W-2 totals must match four 941s this repo already files. NewSend now journals a hash, a client id, and a deposit id. It still does not store the wages.

Questions this design answers

Can IRIS carry Form W-2?
No. The research page assigns IRIS to information returns such as 1099 and W-2G, and says it does not take Form W-2. W-2G is a different form.
Should the writer call SendSubmissions?
No. That client builds an IRS archive from return XML and a manifest. A 512-byte wage file is not that archive.
When does the 941-X checkbox get filed?
When someone submits a 941-X. The schema requires the box. It certifies that W-2s were filed or will be filed. It does not create the wage file.

Open decisions

  • SSA still has to confirm that a Reporting Agent leaves the RE agent indicator blank and puts the client EIN on that employer record.
  • A person at Pyramos still has to finish BSO registration. The User ID is not in this repo, and it leaves with the employee. Register two people.
  • The payroll database has to name which tax_type_id values are federal income tax, Social Security, and Medicare, and whether government_no is the SSN.
  • State files wait until the unread Georgia layout and the missing tax year 2026 booklets are in hand.
