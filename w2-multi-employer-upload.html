W-2 wage reporting · TY2026 · Pyramos as third-party submitter

Ten employers, one upload

Pyramos files W-2s to Social Security for ten client companies. This page covers how that one upload is arranged: who signs it, where each client's EIN goes, whether to send one file or ten, and what the current wagefile code still needs.

The two-sentence version

Pyramos logs in to Business Services Online once and uploads one EFW2 file. The file opens with a Pyramos RA record, then holds one RE block for each client, each carrying that client's own EIN.

Each employee's earnings post to the EIN in their client's RE record. Pyramos only signs the upload. It never appears as the employer.

01

The problem: one login, ten employers' earnings

Say Client C has 260 employees and Client F has 170. Social Security credits each person's wages to a lifetime earnings record that it ties to an employer EIN. If the file names Pyramos as the employer, 2,000 people's 2026 earnings land under Pyramos's EIN. Every client then gets a mismatch notice, because its Forms 941 report wages that its W-2s never matched.

The EFW2 format separates the two roles. One record says who is sending the file. A separate record, repeated once per company, says who paid the wages.

Why position 7 stays blank
Position 7 is for agents who file under their own EIN: Form 2678 agents (code 1), common paymasters (2), and Section 3504 agents (3). A Form 8655 Reporting Agent such as Pyramos files and deposits under the client's EIN, so none of the codes apply. This reading is inferred from Publication 42-007, not quoted from it. Confirm it with an SSA Employer Services Liaison Officer (1-800-772-6270) before the first live file. The writer already follows it: EmployerWage.java:5.

Worked example: does 2,000 W-2s fit?

Ten clients with 420, 310, 260, 220, 190, 170, 150, 120, 90 and 70 employees add up to 2,000. The writer ends each 512-byte record with CRLF, so each line is 514 bytes on disk.

Analogy
Pyramos is a courier carrying ten sealed letters in one bag. The courier signs the delivery slip (RA). Each letter is addressed to its own mailbox (the client EIN in RE), and the mailroom sorts by the address on each letter, not by the courier's name.
Where this breaks
A real mailroom delivers the nine good letters and returns the bad one. SSA does not. If the file is returned, you resubmit the entire corrected file, with RA position 29 = 1 and the original Wage File Identifier (WFID) in positions 30–35, within 45 days. One client's blank contact phone holds up all ten. The courier's signature is also a legal statement made under penalty of perjury, covering every letter in the bag.
05

One file or ten?

All three options use the same example: ten clients, and Client F's contact phone is blank.

Recommended · combined

One file, ten RE blocks

  • 1 upload, 1 AccuWage run, 1 WFID to store
  • SSA's stated preference: "We encourage you to file combined reports"
  • Client F's blank phone returns the whole file. All ten resubmit together.
Pick this if: every client's data is final by mid-January and the local validator plus AccuWage pass before upload.
Isolated · per client

Ten files, one RE each

  • 10 uploads, 10 AccuWage runs, 10 WFIDs
  • Client F's file comes back. The other nine move on to processing.
  • Ten times the manual BSO work, and each upload is a live filing
Pick this if: clients' data arrives at very different times, or one client's data is known to be messy.
Hybrid · ready + late

Combined file for ready clients, a second file for late ones

  • Send the nine ready clients now and Client F once it is fixed
  • Each file has its own RA and its own WFID
  • Needs a client filter on the build. Today's code has none (gap 5).
Pick this if: the February 1, 2027 deadline is close and one client is still missing data.
The rule that makes any split safe
Each client EIN may appear in only one live file per tax year. If Client F is in both the combined file and a late file, SSA posts its employees' wages twice, and fixing that takes W-2c corrections. WageFileManifest.employerEins already records which EINs each run holds, so the guard has the data it needs.
06

What to arrange: once vs. per client

Once, for Pyramos
  • Two people register in BSO as third-party submitters, with Pyramos's EIN and addressLogin.gov or ID.me. SSA mails an activation code to Pyramos's IRS address of record, usually within 2 weeks. BSO User IDs stay with the person, which is why two people register.
  • Request Wage Reporting and SSNVS (SSA's SSN verification service) accessSSNVS checks each name/SSN pair under the client's EIN. Run it at hire and again before the filing season.
  • Call an SSA Employer Services Liaison Officer to confirm the RE treatmentClient EIN in 8–16, position 7 blank, for a Form 8655 agent
  • Add a client-assurance clause to each service agreementForm 8655 does not cover W-2s. The RA signature rests on "assurances provided by the client" (Pub 42-007 §5.2).
  • Set MEF_BSO_USER_ID in the environment, never in the repo
Per client, per tax year
  • EIN, legal name, and delivery address exactly as the IRS holds them
  • Contact name, phone and e-mailRequired since TY2025. "Submissions will be returned if any of these fields are left blank."
  • Kind of Employer (RE 174) and Employment Code (RE 219)A 501(c) nonprofit is T, not N. A Form 944 filer is F, not R.
  • Employer Signature PIN, if the client opted in (RE 319–328, new for TY2026)Without it, SSA does not process that client's report
  • Closed in 2026? Set the terminating-business flag (RE 26)
  • Totals reconciled to that client's four 941 quarters, using 941-X column 1 where amended

What the code needs before ten clients

The writer already loops over many employers, and the validator already checks each RE block's RT against its RW rows. These gaps only show up once real clients differ from the one-employer Orchid fixture.

08

The season, in order

Oct – Nov 2026

Register and agree

Two BSO third-party registrations, the SSA call about the RE treatment, client-assurance clauses, and collecting the per-client fields. SSA plans an updated authorization system for December 2026, so re-read its W-2 News page before the season.

Dec 8, 2026

BSO opens for TY2026

Run SSNVS on every client's employee list. Reconcile each client's year to its four 941 quarters.

Jan 2027

Build, check, upload

POST /api/mef/wage-files builds and validates the combined file. A person runs AccuWage Online, zips one wage file per .zip, uploads it, and stores the WFID with POST /api/mef/wage-files/{id}/receipt.

Feb 1, 2027

Due date for every client

The deadline is the same for all ten. A late client is the one case that justifies the hybrid split.

+45 days

If the file is returned

Resubmit the whole saved file with RA 29 = 1 and the WFID, using WageFileService.resubmit. One 15-day extension exists. Wrong data in a completed file is a W-2c, which is a different specification.

Separate from this upload
SSA forwards nothing to the states. Ten of Pyramos's eleven payroll jurisdictions want their own W-2 file on their own portal. Ohio rejects any file that contains non-Ohio RS records, so it needs a filtered single-state file. See w2-efile-research.html for the state-by-state list.
