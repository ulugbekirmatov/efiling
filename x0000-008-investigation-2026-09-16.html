Every explanation we tested, and how it died

Composer intent is not evidence. Each explanation had to match the artifact IRS receives: the wire bytes and the zip entries. A Java change that never reaches those bytes is not a fix.

REFUTED H1. Return root missing xmlns:efile

What we thought. X0000-008 names the Return root, so xmlns:efile was missing.

What we did. Live send at 21:05:42 with the corrected composer.

Evidence. Submission 10219220262591hv5qt1. Wire root is <Return xmlns="http://www.irs.gov/efile" xmlns:efile="http://www.irs.gov/efile" returnVersion="2026Q1v4.0">.

COSMETIC H2. Repeated default xmlns on spliced Filer and ReturnData

What we thought. Spliced Filer and ReturnData fragments repeated the default xmlns and broke the root.

What we did. inDefaultNs() strips those repeats. The composed return validates against Return941.xsd.

Evidence. ReportingAgentReturnTest green. Schema review found none on every row. Cannot explain a root-element error.

UNTESTED H3. Manifest root missing xmlns:efile

What we thought. The manifest is the only XML in the zip without the efile prefix, so ATS might be reading that root.

What we did. Validated with xmllint against efileAttachments.xsd. Did not resend with the prefix added.

Evidence. NewSendManifestXml.java line 26. Rule text names Return. No IRS artifact requires the prefix.

REFUTED H4. Inspector SOAP handler alters the outbound MIME

What we thought. The inspector handler rewrites outbound MIME and corrupts the attachment.

What we did. Local TLS sink at localhost:9443, inspector on and off, after a real IRS login.

Evidence. Both captures 10003 bytes, Content-Length 9460, correct Return root. Copies in .audit/wire-capture-2026-09-16/.

REFUTED H5. Zip bytes differ from the composer

What we thought. Zip packaging added a BOM, changed charset, or re-serialized the return.

What we did. Rebuilt the SDK archive with SubmissionArchiveBytesDumpTest and compared bytes.

Evidence. cmp identical to the ring return.xml. First bytes 3c3f786d. No BOM. Zero non-ASCII. UTF-8. Deflate entries.

RULED OUT H6. Zip entry names with leading slash

What we thought. Leading slashes on zip entry names were a deviation that ATS maps to X0000-008.

What we did. Read Pub 5446. SDK ZipArchiveProcessing uses the same constants. Untested live.

Evidence. Pub 5446 names /manifest/manifest.xml and /xml/submission.xml with the leading slash.

REFUTED H7. returnVersion 2026Q1v4.0 not active in ATS

What we thought. ATS still wanted an older returnVersion.

What we did. Read the IRS status page for tax year 2026 employment tax MeF schemas and business rules.

Evidence. 2026Q1v4.0 posted 11/6/2025, ATS start 12/7/2025, Production start 1/13/2026, Active. v2.0 and v3.0 Inactive.

NOT THIS CODE H8. Missing or placeholder Software ID

What we did. Compared the ack text to 941-BusinessRules-TY2026Q1v4.0.xlsm.

Evidence. XML carries 12345678. R0000-904-03 is a later database rule with its own text and does not name ATS.
